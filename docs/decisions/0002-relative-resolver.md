# 0002. 상대 날짜 해석기

- 상태: 채택 (0-3 세션, 2026-10-27. 6절은 같은 날 JS 결정 반영)
- 관련: PRD 4.2·5.1·5.3, ADR 0001 7·8절
- 코드: `core/src/relative.rs`, `core/src/holidays.rs`, `core/tests/relative_dates.rs`, `scripts/update_holidays.py`

## 배경

LLM이 낸 `relative` 중간 표현을 결정적 코드로 날짜·시각으로 확정해야 한다 (CLAUDE.md 규칙 2). 규칙은 PRD 5.3 표와 ADR 0001 7·8절의 JS 결정을 따른다. 다만 PRD가 정하지 않은 경우가 많아서, 이 문서에 이번에 정한 해석을 적는다. 표의 모든 행은 `core/tests/relative_dates.rs`에 테스트로 있다 (기준일 2026-10-19 월요일).

## 결정

### 1. 인터페이스

- `Resolver::new(&ParseContext, &HolidayTable)`
- `resolve(field, "start")`: 기준일에서 출발하는 필드를 확정한다
- `resolve_end(field, &start, "end")`: 종료 필드를 확정한다. 날짜 표현이 없으면 시작일을 쓰고, 오전·오후가 없으면 시작 이후 가장 가까운 시각을 고른다 ("오후 2시~4시" → 16:00, "11시~1시" → 13:00)
- 결과 `Resolved { date, time: Option, ambiguities }`
  - `time`이 None이면 시각 표현이 없다는 뜻이다 (종일 후보)
  - 시간대는 아직 붙이지 않는다
- 오류 `ResolveError`
  - `Empty`: explicit·relative 둘 다 없음
  - `Invalid`: 25시, 2/30처럼 있을 수 없는 값
  - `UnknownHoliday`: 공휴일 테이블에 없는 이름

### 2. explicit과 relative가 둘 다 있으면

원문에 적힌 절대 날짜(`explicit`)를 쓴다. 두 계산이 다르면 `explicit_relative_mismatch` 플래그를 세우고, relative 계산값을 대안으로 남긴다 (PRD 5.1).

### 3. 날짜 계산 순서

기준 날짜를 하나 정하고, 마지막에 `day_offset`을 더한다. 기준 날짜는 아래 순서로 먼저 해당하는 것을 쓴다.

1. `holiday`
2. 월·일 표현 (`month`, `day`, `month_offset`, `month_period`)
3. 주 표현 (`week_offset`, `weekday`)
4. 위 셋이 없으면 기준일. 종료 필드면 시작일

그래서 "내일"은 기준일 + 1이고, "담주 월 다음날"은 담주 월 + 1이다.

| 표현 | 해석 | PRD에 없어 이번에 정한 부분 |
| --- | --- | --- |
| 이번 주 X / 담주 X / 다담주 X | 주 시작 요일(`WeekRules.start`)로 기준일이 속한 주를 잡고, 그 주 + N주의 X요일 | — |
| 기준일이 토·일일 때 "이번 주 X" | 다음 주로 넘긴다 | **이미 지난 날일 때만 넘긴다.** 토요일 기준 "이번 주 일요일"은 내일이다 |
| 다음 주 / 이번 주 (요일 없음) | 그 주의 첫날. 이번 주면 오늘 | 범위는 가장 빠른 날 (8절 2번과 같은 원칙) |
| 금요일에 (주 표현 없음) | 오늘 포함 다가오는 그 요일 | 오늘이 금요일이면 오늘 |
| 24일 | 오늘 이후 가장 가까운 24일. 그 날이 없는 달(31일)은 건너뛴다 | 건너뛰기 |
| 10/24 (연도 누락) | 오늘 이후면 올해. 지났고 6개월 이내면 올해, 6개월 넘게 지났으면 내년 | 지난 날짜로 해석될 때만 `year_missing` 플래그와 다른 연도 대안을 남긴다. 정확히 6개월 전은 "이내"(올해)로 본다 |
| 11월 (일 없음) | 1일. 이번 달이면 오늘 | 범위로 본다 |
| 월초·상순 / 중순 / 하순·월말 | 1일 / 11일 / 21일 (ADR 0001 8절) | 기준일이 그 구간 안이면 오늘. 월 없이 쓴 구간이 이번 달에 이미 끝났으면 다음 달 |
| 다음 달 24일 / 이번 달 24일 | 그 달의 24일 | 이미 지났어도 넘기지 않는다 (원문이 달을 지정했으므로) |
| 추석 / 설 전날 / 추석 연휴 | 공휴일 테이블에서 같은 이름이 이어진 묶음 중 오늘 이후에 끝나는 첫 묶음을 잡는다. 당일은 묶음의 가운데 날이고, 여기에 `holiday.day_offset`을 더한다. `whole_period`("연휴")면 묶음 첫날 | 7절 |

### 4. 시각

| 입력 | 결과 | 비고 |
| --- | --- | --- |
| `time_word`만 | `TimeDefaults` 기본 시각 (새벽 05·아침 08·오전 10·점심 12·오후 13·저녁 19·밤 19시) | ADR 0001 8절 |
| 0시, 13~23시 | 그대로 (24시간제) | `time_word`는 무시 |
| 오전·새벽 + N시 | N시. 12시는 0시 | |
| 아침 + N시 | N시 | |
| 점심 + 1~5시 | 오후 (13~17시) | "점심 1시" = 13:00 |
| 오후·저녁 + 1~11시 | +12시간 | |
| 밤 + 6~11시 | +12시간 | |
| 밤 + 12시 / 1~5시 | **다음 날** 0시 / 1~5시 | "밤 12시"는 그날 자정을 넘긴 시각으로 본다 |

| 분 | `minute`, 없으면 0 | |

### 5. 공휴일 테이블

- `core/data/holidays.json`(`[{date, name}]`)을 `include_str!`로 내장한다. `HolidayTable::bundled()`로 읽는다
- `scripts/update_holidays.py <연도…>`가 특일 정보 API(`getRestDeInfo`)를 호출해 이 파일을 갱신한다
  - `isHoliday == "Y"`인 항목만 넣는다
  - 지정한 연도의 기존 항목은 새 응답으로 바꾼다
- 2026·2027년 데이터 46건은 JS가 로컬에서 스크립트를 돌려 커밋했다 (`6cbafcb`). 클라우드 세션은 data.go.kr 접속이 막혀 있다
- 테이블에 없는 연도나 이름은 `UnknownHoliday`가 된다. 날짜를 손으로 채우지 않는다 (CLAUDE.md 규칙 8)

### 6. JS 결정 (2026-10-27)

처음 미결이던 4건 중 3건에 대한 결정이다. PRD 4.2·5.3에도 반영했다.

1. **주말의 "이번 주"는 이미 지난 요일만 다음 주로 넘긴다.** 토요일 기준 "이번 주 일요일"은 내일이다. 3절 표의 해석을 그대로 확정한다
2. **근무시간 기본값은 09:00~18:00이고, 설정에서 바꿀 수 있다.** `ParseContext.working_hours`를 `Option`이 아닌 `WorkingHours`로 바꾸고 기본값을 넣었다. 그래서 오전·오후 표시 없는 7·8시는 기본으로 오후(19·20시), 9~11시는 오전이다
3. **"밤 12시"·"밤 1~5시"는 다음 날로 넘긴다.** 4절 표의 해석을 그대로 확정한다

### 7. 명절 당일은 연휴의 가운데 날 (2026-10-27, 실제 데이터 확인)

특일 정보 API는 설날·추석 연휴 3일을 모두 같은 이름("설날"·"추석")으로 준다. 2026년 설날은 02-16~18, 추석은 09-24~26이다. 이름만으로는 당일을 알 수 없으므로 아래처럼 정한다.

- 당일은 묶음의 가운데 날이다 (2026 설날 02-17, 추석 09-25). 2일짜리 묶음이면 첫날이다
- "설 전날"은 당일 − 1이다. 3일 연휴면 연휴 첫날이 된다
- "추석 연휴"처럼 연휴 전체를 가리키면 `HolidayRef.whole_period: true`로 받고, 연휴 첫날로 확정한다. 이 필드는 스키마에 새로 추가했다
- 대체공휴일은 "대체공휴일(설날)"처럼 이름이 달라서 묶음에 섞이지 않는다

## 대안

- `day_offset`을 다른 표현과 섞지 않고 단독으로만 허용하기: "담주 월 다음날"을 표현할 수 없어서 기각
- 주말 넘김 규칙을 PRD 문구 그대로 적용(토·일이면 무조건 다음 주): 토요일에 "이번 주 일요일"이 8일 뒤가 되어 기각 (6절 1번에서 확정)
- explicit·relative가 다를 때 relative를 쓰기: 원문에 적힌 절대 날짜가 더 믿을 만해서 기각

## 미결

없음. 처음 4건은 6·7절에서 모두 결정됐다.
